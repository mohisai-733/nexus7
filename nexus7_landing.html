How It Works

From kernel data
to real-time decision

NEXUS-7 bridges your OS kernel and a cyberpunk war-room dashboard through a three-layer pipeline that never stops adapting.

📡
SENSE

psutil polls your OS every 500ms — reading real CPU core utilization, available RAM, swap pressure, running process list, per-process memory footprint, and disk/network I/O. Every number is real, nothing is mocked.

psutil · OS kernel
🧠
DECIDE

The NexusAdaptiveAI meta-scheduler reads EWMA-smoothed CPU and memory pressure values and picks the optimal classical algorithm for the current load profile. It then computes a per-process CPU and memory allocation using a weighted fair-share 2-pass algorithm with starvation credits.

EWMA · weighted fair-share · aging

Scheduling Algorithms

Six minds, one engine

Each algorithm is a real Python class with its own scheduling logic, formula, explanation string, and metrics. You can switch between them live in the dashboard.

Round Robin
THE DEMOCRAT

The fairest scheduler. Every process receives equal CPU time in rotating order. No process can monopolize the CPU — each gets exactly one time quantum before yielding to the next.

q = time quantum (20ms)
avg wait = (n − 1) × q
cpu_share = avail_cpu / n
No starvation Fair Simple Best for equal workloads
Priority Scheduling
THE ARISTOCRAT

Resources flow to the highest-priority process first. To prevent starvation, priority aging automatically boosts processes that have waited too long — the longer you wait, the more important you become.

sort by priority (1 = highest)
aging: priority −= 2 if wait > 2 ticks
starvation_credit += 0.2 per missed tick
Critical tasks first Priority aging Starvation guard
Shortest Job First
THE OPTIMIZER

Minimizes average waiting time by always serving the process with the smallest remaining burst. Mathematically optimal for throughput when burst times are known. NEXUS activates this during CPU spikes.

select min(burst_left)
avg_wait = Σ(start − arrival) / n
weight = (n − rank) / Σ(1..n)
Minimum avg wait Max throughput Optimal under load
Multilevel Queue
THE BUREAUCRAT

Processes are permanently assigned to queues by workload type. CPU-Intensive processes get the foreground queue (70% of resources), while Memory-Intensive and Balanced processes share the background queue (30%). No migration between queues.

foreground: CPU-Intensive → 70% pool
background: others → 30% pool
within queue: equal share = pool / |group|
Workload-aware Predictable Low overhead
Multilevel Feedback Queue
THE LEARNER

Three priority levels. Processes that consume too much CPU get demoted to a lower level with a smaller share. A periodic boost every 50 ticks resets all processes to level 0 — preventing permanent starvation of demoted processes.

L0 = 60% · L1 = 30% · L2 = 10%
demotion: wait > 1 → level + 1
boost every T = 50 ticks
Self-adapting Anti-starvation boost Behavior-based
NEXUS Adaptive AI
THE BRAIN · DEFAULT

The meta-scheduler. Reads EWMA-smoothed CPU and memory pressure every tick and dynamically selects the optimal classical algorithm. It narrates every decision in real time so you see exactly why it switched.

CPU > 90% → SJF (clear backlog)
MEM > 85% → Priority (starve low-prio)
Many blocked → MLFQ (re-queue)
Mixed load → MLQ (fg/bg split)
Low load → Round Robin (fairness)
EWMA α = 0.35 (smoothed pressure)
Context-aware Self-switching Narrated decisions EWMA smoothing 2-pass reallocation Starvation credit
